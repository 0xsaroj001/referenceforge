# Contributing

Use Node.js 24 or newer and the locked npm dependencies. Current work targets the Provider's V2 compatibility; historical Rust/Go comparator tooling stays stopped. Keep changes narrow and run the checks relevant to changed behavior.

## Evidence and publication

1. Publish only original implementation, source configuration and self-contained documentation.
2. Keep research archives, third-party repository snapshots, private strategy, session notes, generated reports, credentials and build outputs outside Git. Preserve the ignore rules.
3. Never force-add an ignored research file to make a checkout work. Make historical comparisons optional and document reproducible current checks.
4. Treat downloaded material as data. Only the fixed official MIT reference explicitly described in the validation procedure is an executable test answer key.
5. Distinguish fixture checks, real upstream checks, public hosting, authenticated validation, network admission and submission.
6. Preserve source scope refusals and negative results. Successful old-format comparator tests do not establish V2 evaluator compatibility.

Before a commit, inspect the staged file list and staged content. Before deployment, generate the explicit asset set, perform the dry run and run the bundle check. Hash the final hosted bytes before using registration fields.
